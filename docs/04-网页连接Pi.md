## 1. 这一步究竟增加了什么

上一轮，需要在服务器终端运行 `npm run pi:sdk`，程序会读取固定的 prompt.txt，再调用 Pi。

这一轮，可以在自己电脑的浏览器中输入要求并点击发送。服务器收到文字后，仍然调用同一个 Pi SDK；Pi 执行完毕，服务器把结果送回网页。

新增的是用户入口、接收请求的服务和任务目录管理。Pi 的模型通信、工具参数处理、执行循环没有被我们重新实现。MiniMax-M3 也没有被安装到服务器：服务器上的 Pi 通过 API 请求 MiniMax 的模型服务。

```text
你的电脑                               远端服务器
浏览器中的网页
  输入文字、点击发送
       │ HTTP 请求，经过 SSH 隧道
       └────────────────────────────→ Node HTTP 服务
                                         │ 接收并检查任务
                                         ↓
                                     runWebTask()
                                         │ 建立编号、目录
                                         ↓
                                     runPiTask()
                                         │ 调用 Pi SDK
                                         ↓
                                     Pi ↔ MiniMax API
                                         │ read/write
                                         ↓
                                     服务器上的任务文件
       ←───────────────────────────── 最终 JSON 响应
  网页显示 Pi 的回答
```

HTTP 可以先理解为浏览器与服务器之间约定的收发方式。JSON 是双方交换的结构化文本。例如网页发的是 `{"message":"请计算平均值"}`，服务返回包含 `answer`、`taskId` 等字段的对象。

## 3. 按一次点击的顺序读我们的文件

以下路径均相对于项目根目录。服务器根目录是 `/home/hanwen/Project/project/siNRA-pi`。

### 第一步：浏览器拿到页面

`scripts/web.mjs` 启动 HTTP 服务，默认监听 `127.0.0.1:3000`。这个进程需要持续运行，才能随时接收浏览器请求。

`src/server.mjs` 只提供三个页面文件：

- `public/index.html`：页面结构，例如输入框、按钮、回答区。
- `public/style.css`：页面外观，例如颜色、间距、窄屏布局。
- `public/app.js`：浏览器里的行为，例如点击按钮后发送请求。

这三个文件会被传给浏览器；密钥文件、后端源码、运行日志不会作为网页资源提供。网页无需持有 MiniMax API Key。

### 第二步：点击发送，浏览器发送文字

`public/app.js` 监听表单的 submit 事件，并调用：

```javascript
fetch("/v1/tasks", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ message }),
});
```

`fetch` 是浏览器已有的网络请求能力。“/v1/tasks”是我们在服务器上约定的入口，不是一个磁盘目录。

发送后页面显示等待状态，禁用重复发送。返回后用 `textContent` 显示文字，因此模型输出的 HTML 不会被当成可执行网页。当前保留 Markdown 原文，没有加入 Markdown 渲染器。

### 第三步：服务器接住请求

`src/server.mjs` 检查：是不是正确的请求地址和 JSON、输入是否为空或超过 4000 个字符、是否已有任务正在运行。

确认后执行 `runTask(body.message.trim())`。这里的 `runTask` 默认就是 `runWebTask`。这使 HTTP 的职责与 Agent 执行分开：以后改执行方式时，网页收发部分不用跟着全部重写。

本阶段全服务同时只运行一个任务。失败会释放占用，下一次还能发送；不会把服务商原始错误或密钥返回网页。

### 第四步：给这次任务一个自己的位置

`src/web-task.mjs` 为每次请求生成 UUID，即几乎不会重复的一串任务编号，并创建：

```text
workspaces/web/<任务编号>/numbers.csv
workspaces/web/<任务编号>/result.json      由 Agent 按要求生成
runtime/web/<任务编号>.events.jsonl       由应用记录事件
```

每个任务开始时，程序把已有四个数的 CSV 样例复制进去。程序并不替模型计算 count、sum、mean，也不会预先写好 result.json。

分开目录有两个直观作用：再次发送不会覆盖前一次结果；看到任务编号，就能找到对应的文件与执行记录。

### 第五步：调用 Pi，执行任务

`src/pi-session.mjs` 从上一轮 SDK 示例中抽出了共享函数：

1. `createLearningSession()`：准备项目内配置，读取服务器凭据，选 MiniMax-M3，创建 Pi 内存会话。
2. `runPiTask()`：先订阅事件，再 `await session.prompt(prompt)`；结束后检查完成状态，提取最终回答，并释放会话。

`scripts/pi-sdk.mjs` 现在也调用这些函数，仍可运行上一轮固定示例。这样以后更新模型配置或事件处理，只需修改共享实现。

本轮没有重新写“模型思考 → 决定调用哪个工具 → 执行 → 把结果送回模型 → 继续”的循环；它仍由 Pi SDK 提供。我们调用的是 Pi 1.2.0 的公开接口：createAgentSession、createReadToolDefinition、createWriteToolDefinition 等。

代码设有 180 秒执行计时及最多 12 次模型响应的限制；触发后请求 Pi 中止，任务按失败返回。这是应用的中止请求，不是强杀进程的硬实时保障，也不代表超时/限额分支已做真实服务商故障实验。4,096 maxTokens 是单次响应上限，不是整项任务的总预算。

### 第六步：工具真正读写文件

`src/workspace-files.mjs` 为 Pi 原生 read/write 提供底层文件操作，检查文件是否在本次任务目录、是否涉及链接、大小是否超过 1 MiB。

为什么要加这一层：`cwd` 只是相对路径的起点，原生工具仍可能接受绝对路径或 `../`。从固定提示改为网页自由输入后，需要由程序落实文件范围，不能只在提示词里说“请不要越界”。

模型提出“读取 numbers.csv”，Pi 解析工具参数，我们的操作函数检查路径，操作系统读取文件，再把内容交回 Pi。写入同理。

这里只开放普通文本 read/write，没有命令执行、扩展或 MCP，也没有操作系统沙箱。范围检查不承诺抵抗其他本地进程同时替换文件产生的竞态；当前是个人学习服务。

### 第七步：结果回到页面

只有 Pi 正常完成、最后一条模型消息正常结束且有文字回答，才返回成功结果。响应包含回答、编号、文件位置和调用次数。

但“正常完成”仍不等于“每个任意任务的答案正确”。所以统计练习另用 `scripts/verify-first-task.mjs --web <编号>` 独立计算并检查工具轨迹。它不调用模型，不相信回答中自称的“正确”。

## 4. 在哪里运行、用哪个网址

服务器上：

```bash
cd /home/hanwen/Project/project/siNRA-pi
export PATH=/home/hanwen/.nvm/versions/node/v24.16.0/bin:$PATH
npm run web
```

本机终端建立 SSH 隧道：

```powershell
ssh -N -T -p 1369 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 127.0.0.1:3000:127.0.0.1:3000 hanwen@39.96.171.247
```

然后浏览器访问 `http://127.0.0.1:3000`。已经有服务或隧道运行时，不要重复启动占用同一端口的进程。

网址里的 127.0.0.1 指你自己的电脑。SSH 把本机 3000 端口收到的数据转给服务器的 3000 端口；3000 是网页服务端口，1369 是 SSH 登录端口。服务器的服务只监听回环地址，没有开放公网网页端口。本轮没有购买域名、配置 HTTPS 或建立公共访问。

本轮已在后台启动服务器和本机隧道。服务器日志为项目内 `runtime/web-server.log`。服务器/电脑重启、SSH 断线后，需要重新启动相应进程；本轮没有配置开机自启。
