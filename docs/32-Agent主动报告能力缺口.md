# 第11D步：Agent 主动报告能力缺口

本步承接 [Curator 建议交给 Builder](31-Curator建议交给Builder.md)，补上另一种发现工具需求的入口：`report_tool_gap`。上一轮解决“有建议之后怎样构建”，这一轮解决“任务中的 Pi 怎样明确提出缺少某种能力”。

## 从一个具体例子开始

假设你让 Pi 比较两条 RNA 的结构。Pi 检查现有工具后认为：“我能读取这两份数据，但没有合适的方法计算结构距离。”过去，这句话可能只出现在聊天正文里。系统虽然保存了聊天，却没有一个专门的结构说明它究竟缺什么、期望输入输出是什么、涉及哪次任务。

现在 Pi 可以调用 `report_tool_gap`，提交一份结构化报告：

```json
{
  "capability": "比较 RNA 结构",
  "blocking": true,
  "reason": "现有工具未提供所需的结构距离计算。",
  "desiredInput": { "structures": ["结构表示"] },
  "desiredOutput": { "distance": "number" },
  "evidenceEventIds": []
}
```

这是说明字段的虚构例子，不是业务任务的实际结果。`blocking: true` 表示 **Agent 认为这个缺口阻碍了任务**，不会让后端自动中止任务。`evidenceEventIds` 是已经保存的事件编号；可以留空，因为缺口报告不一定发生在工具调用失败之后。

报告保存成功，只表示“系统收到了这项主张”。它不证明工具确实缺失，也不证明新工具值得开发，更不等于批准 Agent 安装软件。

## 原仓库的这条链路

参考版本固定为 `sirna-pi-agent-service-refactor@67d2754`。

| 原仓库文件 | 原有职责 | 本步如何对应 |
|---|---|---|
| `packages/domain/sirna-tools/sirna-tools.ts` | 定义 `report_tool_gap` 的参数与工具调用 | 独立的 `tool-gap-tools.mjs` 定义同名工具，复用现有 MCP 服务 |
| `apps/api/router.ts` | 接收 `/v1/tool-gaps`，绑定任务与执行轮，按能力去重 | 私有工具网关接收同一路径，通过已激活的执行凭证取得身份 |
| `tool-curation-store.ts` | 保存缺口报告与能力键 | 单独的 `tool-gap-store.mjs` 保存报告，避免修改旧审查数据库结构 |
| `tool-curation-coordinator.ts` | 已结束轮次有报告时，可以触发 `online_gap` 审查 | 报告进入结束轮次的预览，由人点击送审 |
| `tool-curation-trace.ts`、`agent-tool-curator.ts` | 把报告和引用事件交给 Curator | 冻结完整报告、内容摘要和引用事件，核验 Curator 回答引用 |

原版的 `online_gap` 是一种触发来源：任务执行中发现了缺口，轮次结束后审查。它不表示必须在任务还运行时启动另一个 Agent。本学习版沿用名称与职责，同时继续保留人工审查、人工交接和人工批准；没有接入原版自动观察与七天能力冷却。

## 一份报告怎样走到网页

```mermaid
flowchart LR
  A[任务容器中的 Pi] -->|report_tool_gap| B[MCP 客户端]
  B --> C[私有 relay 与工具网关]
  C --> D[检查真实任务和执行轮]
  D --> E[独立 gap SQLite 保存报告]
  E --> F[本轮结束后的网页预览]
  F -->|人点击送审| G[冻结证据与独立 Curator]
  G --> H[skip 或 candidate]
  H -->|candidate且人交接| I[已有 Builder 流程]
```

Pi 只填写能力、原因和草案。任务编号、执行会话、容器编号、执行轮次等来源由后端从已激活的凭证取得，不能通过报告正文自行填写。这与普通网页表单不同：网页没有提供“替 Agent 伪造一份报告”的写入接口。

同一执行轮内，“Compare RNA structures”和规范化后相同的能力名称只保留第一份报告。程序不会把后一次提交悄悄覆盖到旧报告上；新保存返回 HTTP 202，重复返回 HTTP 200 和原来的编号。这个去重机制控制重复记录，不能识别所有语义相同的需求。

这里有一项明确的本地差异：原版能力键只保留英文小写字母、数字和基本汉字，空结果使用统一占位名；学习版保留其他语言的 Unicode 字母与数字，空结果则拒绝。目的是不让带重音字母等名称被丢掉，也不把没有有效名称的报告合并到同一个占位键。两者都按规范化后的键去重，算法并非逐字一致。

## 按文件逐层阅读

先读 `packages/domain/sirna-tools/tool-gap-tools.mjs`。这里是模型看到的工具说明和参数合同：告诉 Pi 什么时候报告、要填什么、报告不会直接创建工具。它不是领域计算工具，因此单独作为报告类接入 MCP，不标成只读或无副作用。

然后读 `apps/mcp/tool-gap-client.mjs` 与 `apps/mcp/remote-server.mjs`。前者每次调用读取当前执行上下文，将参数发给固定接口；后者在配置 `SIRNA_TOOL_GAP_URL` 时把报告工具加入服务。没有自动重试，避免网络不确定时暗中再次发送。

接下来读 `containers/agent-tools-relay/relay.mjs`、`apps/api/tool-gap-api.mjs` 和 `apps/api/agent-tools.mjs`。relay 是任务网络到宿主私有 Unix socket 的转接点；网关在读取请求正文之前和之后核对凭证，并把已接受的调用纳入关闭排空。任务在上传报告期间结束或凭证失效，就不能继续落库。

真正的业务规则在 `packages/extensions/tool-curation/tool-gap-service.mjs`：当前任务必须仍在执行、运行号与消息必须对应、引用事件必须属于本轮、审查材料还没有冻结。这里没有“调用 Curator”或“创建工具”的操作。

`tool-gap-contract.mjs` 统一检查字段、大小、来源和内容摘要，复用已有脱敏器；`tool-gap-store.mjs` 负责独立的 `runtime/tool-gaps/gaps.sqlite`。SQLite 是本地数据库文件，进程重启后报告仍然存在。数据库唯一约束处理同一能力的竞争写入；报告保存后保持不变。

`tool-curation-preview.mjs` 和 `tool-curation-trace.mjs` 把报告加入结束轮次的预览。原来的重复调用线索仍按原规则计算；报告不会被伪装成“三次调用”。因此可能同时出现 `signals: []` 和非空 `gapReports`：没有重复行为线索，但确实有一项明确报告，可以交给 Curator 判断。

人点击送审后，`tool-curation-evidence.mjs` 把报告与它引用的公共事件冻结在 trace 中。SHA-256 仍只是材料的内容指纹，用于发现材料变化；它不能给报告的真实性评分。没有缺口报告时，原来的预览和摘要规则保持兼容。

`tool-curation-result.mjs` 检查独立 Curator 的回答。若建议来自一个缺口，必须引用该能力的报告编号；不能借用另一个能力的报告，或引用未保存的事件。提示也明确要求把报告当作待检查的主张。合法的 `candidate` 可以继续进入上一轮的构建说明读取与人工交接，但不会自动构建。

`packages/capability-platform/tool-names.mjs` 保存本步新增的保留名称规则，`tool-contract.mjs` 和 `tool-curation-result.mjs` 共用它：不能把新业务工具也命名为 `report_tool_gap` 或其 MCP 别名 `sirna_tools_report_tool_gap`。否则批准后，业务工具会与报告入口重名，MCP 就无法正常列出工具。检查放在候选生成、Builder 读取和实际提案登记之前；登记拒绝时尚未写入提案文件。这里没有把保留名加进旧版摘要所用的工具目录，因此不会使旧预览突然变成“材料已改变”。

最后读 `public/curation.mjs` 与 `apps/api/bootstrap.mjs`：前者把报告显示在“工具线索”页面，展示 Agent 的阻塞判断、原因、输入输出草案和引用；后者把前面这些模块真正连接到正在运行的服务，并安排数据库关闭。

## 为什么限制大小、引用和状态

每轮最多十份不同能力报告，报告数组累计不超过 32 KiB；输入输出草案分别不超过 4 KiB。完整预览和冻结证据仍受 64 KiB 上限约束。超限明确拒绝，不把后半段证据静默丢掉。这些是工程容量边界，不是判定需求价值的规则。

来源检查防止串任务；终态检查防止已结束的执行轮补写新事实；不可变记录防止审查依据被事后替换。事件引用检查只能确认“引用的是这次任务保存过的事件”，不能确认模型对事件的解释正确。

常见秘密字段会被脱敏，但自由文本可能包含程序不知道的私密信息，不能把脱敏当作完整隐私保证。运行凭证本身不会进入报告。

## 在现在的网页上怎样使用

地址仍是通过 SSH 隧道访问的 `http://127.0.0.1:3000/`，不需要换网址。新建网页任务会使用 `agent-compose.yml` 中的新身份 `sirna-pi-learning-tool-gap` 和 `sirna-pi-guest:pi1.2.0-mcp5` 镜像。镜像里的 Pi 仍是 1.2.0，新增的是报告工具的接线；模型、原有固定工具和构建工具仍沿已有配置。

已有任务保留原来的运行身份与容器版本，不会被此次部署强制迁移。若要体验新报告入口，应新建任务；旧任务的记录和文件仍可查看。

Pi 在执行中可以自行选择调用 `report_tool_gap`。如果确有报告，本轮结束后打开该任务的“工具线索”，先看能力名称、原因、Agent 的阻塞判断及输入输出草案，再决定是否点击送审。只有 Curator 返回合格的 `candidate`，才会出现可供读取的 Builder 构建说明，并沿上一轮的按钮人工交接。`skip` 表示此次审查不建议继续构建。

没有报告时，网页不会为了演示补出一份报告。生产库目前没有真实缺口报告；本次截图中的正向流程来自明确标记的隔离演示，采用固定审查回答，未向 MiniMax 发送请求。

## 下一步怎样理解

这一轮补的是“发现需求”的第二种入口：一类线索来自重复使用记录，另一类来自 Agent 主动报告。两类线索都要经过独立审查，才能形成待构建建议。

后续可以继续对照原仓库的 coordinator，学习如何自动观察已结束任务、按能力冷却和安排审查，同时保留清晰的执行预算与人工批准边界。自动化调度仍是下一小步，不能把本次报告接口称为完整自进化。
